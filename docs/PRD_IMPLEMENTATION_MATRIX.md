## Metric definitions and limits

- **Response latency:** each selection duration is the elapsed time since the actionable decision boundary; Memory Match uses a two-card comparison as an attempt. Resume/continue boundaries reset the relevant timer. The saved session stores average duration, attempts, start/completion time, patient and game. The summary is `sum(session_average_ms × attempts) / sum(attempts with known duration)` within the selected local-calendar window, grouped by game/difficulty. Unknown values remain unknown; wall-clock session duration is a separate field. Reading/thinking time during an actionable question may be included. These are engagement measurements, not clinical response tests. Demo-seeded sessions are excluded by the analytics queries.
- **Today's routine completion:** `100 × completed enabled reminders scheduled today / enabled reminders scheduled today`. Future times today are included. No denominator means no percentage, not 0% or 100%. Each reminder ID contributes once; the database unique reminder/day index prevents repeated completions. Separate user-created reminder IDs remain separate tasks even if their titles match. Editing/removing/disabling a task changes today's current-plan denominator. Mutable reminders cannot reconstruct a trustworthy historical scheduled-task denominator, so no 7/30-day adherence percentage is claimed.
- No example patient result, `12.4s`, `94%`, battery reading, emergency contact or provider relationship was inserted. Test fixtures are synthetic and confined to disposable tests.

## Local recording privacy, recovery and rollout

Migration `016_voice_memories` appends nullable `audio_path` to `personal_memories`; versions 001–015 remain unchanged. Existing rows retain all prior fields and gain `NULL`. The runner applies it transactionally and idempotently. No hosted migration or production database mutation is required. Existing explicit cloud columns exclude photo and audio paths and media bytes.

Recordings use the existing per-patient `memories/<patient>/` directory with generated filenames. Only validated native cache `.m4a` sources can be copied; maximum accepted file size is 10 MB. A file is copied before its database reference is committed. Failed saves clean up the new managed copy and retain the temporary source for retry; prior audio remains intact. Successful replacement/delete cleans up the old file and reports cleanup failure honestly. A failed unsaved recording can be explicitly discarded. App/process termination can still lose a cache-only unsaved recording; cache recovery after process death is not promised. Successful saved recordings survive normal restart, remain offline, and are excluded from Android backup by existing backup rules. SQLite/media are not encrypted at rest by this change; local profile switching is not authentication.

Recovery for a rollout problem: retain the additive nullable column and roll back application code; do not drop/reseed the database or delete recording files. Rebuild native binaries for `expo-audio` and `expo-battery`. `expo-asset` is explicitly pinned to SDK 54 because it is an audio peer dependency (hoisted unchanged from Expo's nested dependency). Microphone permission is enabled only for this explicit recording feature; camera, broad storage, biometric and overlay restrictions remain. No background recording service is enabled. The ignored local Android manifest's old microphone removal marker was adjusted; generated native files are not committed.
